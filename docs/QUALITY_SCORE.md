# enhance 代码质量评分体系

本文档说明 enhance 项目的代码质量评分体系，用于评估代码的 AI 可维护性。

## 1. 评分维度

### 1.1 编译检查 (20 分)
- 代码能否正常编译
- 无语法错误
- 无类型错误

### 1.2 测试检查 (20 分)
- 测试能否正常运行
- 测试用例覆盖正常和错误路径
- 测试并发安全

### 1.3 格式检查 (10 分)
- 代码格式符合 gofmt 规范
- 无格式错误

### 1.4 静态分析 (10 分)
- 无 go vet 警告
- 无明显代码问题

### 1.5 测试覆盖率 (15 分)
- ≥ 80%: 15 分
- 60-79%: 10 分
- 40-59%: 5 分
- < 40%: 0 分

### 1.6 文件长度检查 (10 分)
- 所有文件 ≤ 500 行
- 无过长文件

### 1.7 函数长度检查 (5 分)
- 所有函数 ≤ 50 行
- 无过长函数

### 1.8 接口设计检查 (5 分)
- 接口方法 ≤ 5 个
- 接口命名符合规范

### 1.9 错误处理检查 (5 分)
- 使用 errors.Is/As
- 无直接错误比较

## 2. 评级标准

### 2.1 优秀 (90-100 分)
- 代码质量非常高
- AI 可维护性优秀
- 符合所有规范

### 2.2 良好 (80-89 分)
- 代码质量良好
- AI 可维护性较好
- 基本符合规范

### 2.3 一般 (70-79 分)
- 代码质量一般
- AI 可维护性需要改进
- 部分规范未遵守

### 2.4 较差 (60-69 分)
- 代码质量较差
- AI 可维护性需要大幅改进
- 多项规范未遵守

### 2.5 很差 (< 60 分)
- 代码质量很差
- AI 可维护性需要全面改进
- 严重违反规范

## 3. 使用方法

### 3.1 运行评分
```bash
./scripts/quality-score.sh
```

### 3.2 查看详细报告
```bash
# 查看测试覆盖率
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out

# 查看格式问题
gofmt -l .

# 查看静态分析问题
go vet ./...
```

## 4. 改进建议

### 4.1 提高测试覆盖率
- 编写更多测试用例
- 覆盖正常和错误路径
- 使用表驱动测试

### 4.2 改善代码格式
- 使用 gofmt 自动格式化
- 配置 IDE 自动格式化

### 4.3 减少静态分析问题
- 使用 go vet 检查代码
- 配置 golangci-lint

### 4.4 优化接口设计
- 保持接口小而精
- 使用组合形成大接口

### 4.5 改善错误处理
- 使用 errors.Is/As
- 包装错误保留上下文
