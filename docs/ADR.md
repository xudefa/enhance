# 架构决策记录（Architecture Decision Records）

本文档记录 enhance 框架的重要架构决策及其原因，帮助开发者和 AI 理解设计意图。

---

## ADR-001: 选择泛型 API 而非反射 API 作为用户接口

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: IoC 容器的用户 API 设计

### 决策

用户 API 使用泛型函数（`Register[T]`, `Get[T]`）而非直接暴露反射方法。

### 理由

- **编译期类型安全**: 泛型在编译期检查类型，避免运行时类型断言错误
- **更好的 IDE 支持**: 泛型 API 提供更好的代码补全和类型提示
- **减少样板代码**: 用户无需手动进行类型断言
- **性能优化**: 减少运行时的反射调用次数

### 后果

- 容器内部仍使用 `reflect.Type` 存储类型信息（Go 接口方法不能有类型参数）
- 用户应始终使用泛型 API，避免直接调用 Container 接口的反射方法

## ADR-002: 使用函数式选项模式而非构造函数参数

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: Bean 注册和容器配置

### 决策

使用函数式选项模式（Functional Options Pattern）提供灵活的配置。

### 理由

- **可扩展性**: 新增选项无需修改构造函数签名
- **可读性**: 选项名称自文档化（`WithScope`, `WithLazy`）
- **默认值**: 可以提供合理的默认值，用户只需覆盖需要的选项
- **类型安全**: 每个选项函数都有明确的类型签名

### 后果

- 选项函数数量增加时，需要保持良好的文档
- 用户需要了解可用的选项及其用途

## ADR-003: 放弃 AOP 模块，采用显式拦截器模式

**日期**: 2024-09-02  
**状态**: 已采纳  
**上下文**: 横切关注点（日志、事务、审计）的处理

### 决策

删除 AOP 模块，改用显式拦截器（Interceptor）模式处理横切关注点。

### 理由

- **Go 惯用法**: AOP 是 Java/Spring 的概念，Go 更倾向于显式而非隐式
- **AI 可读性**: 显式拦截器更容易理解和维护
- **性能**: 避免运行时反射代理的开销
- **简洁性**: 减少框架复杂度，降低学习成本
- **调试友好**: 显式调用链更容易调试和追踪

### 后果

- 用户需要显式注册拦截器，而非使用注解
- 某些场景下代码可能稍微冗长，但更清晰

## ADR-004: 核心框架零外部依赖

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 框架依赖管理

### 决策

核心框架（core、boot、event 等）仅使用 Go 标准库，不引入任何第三方依赖。

### 理由

- **减少依赖冲突**: 避免与用户项目的依赖版本冲突
- **更快的编译**: 减少依赖下载和编译时间
- **更好的可控性**: 核心功能完全由框架控制
- **安全性**: 减少第三方依赖带来的安全风险

### 后果

- 第三方依赖的集成通过 `starter/` 包实现
- 示例代码放在 `examples/` 目录，每个示例有独立的 `go.mod`

## ADR-005: 使用 `doc.go` 集中管理接口定义

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 包内接口和类型定义的组织

### 决策

每个包的对外接口、类型别名、公共结构体定义统一放在 `doc.go` 文件中。

### 理由

- **单一职责**: `doc.go` 只包含定义，不包含实现
- **易于查找**: 开发者可以快速找到包的所有公开接口
- **AI 友好**: AI 可以快速理解包的对外契约
- **文档集中**: 包文档和接口定义在一起

### 后果

- `doc.go` 超过 500 行时，需要创建 `types.go` 分担
- 实现逻辑必须放在其他文件中

## ADR-006: 接口返回而非具体类型返回

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 构造函数和工厂函数的返回类型

### 决策

构造函数返回接口类型，而非具体结构体指针。

### 理由

- **依赖倒置**: 调用方依赖接口而非实现
- **易于测试**: 测试时可以轻松 mock 接口
- **灵活性**: 实现可以随时替换，不影响调用方
- **Go 惯用法**: 符合 Go 的接口设计哲学

### 后果

- 需要类型断言的场景可以使用类型别名（如 `BootErrorStruct`）
- 接口方法数量应保持最小化（1-5 个）

## ADR-007: 使用 `sync.Map` 优化读多写少场景

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: Bean 注册表和实例缓存的并发安全

### 决策

Bean 注册表和实例缓存使用 `sync.Map` 而非 `sync.RWMutex` + `map`。

### 理由

- **性能优化**: Bean 注册是一次性操作，读取是高频操作
- **减少锁竞争**: `sync.Map` 针对读多写少场景优化
- **简化代码**: 无需手动管理读写锁

### 后果

- `sync.Map` 的值必须可比较（不能使用 slice）
- 需要使用包装器（如 `listenerList`）支持 CAS 操作

## ADR-008: 条件化自动配置而非注解驱动

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 自动配置的条件判断

### 决策

使用条件函数（`condition.OnProperty`, `condition.OnBean`）而非注解驱动。

### 理由

- **Go 惯用法**: Go 没有注解，使用函数更符合语言特性
- **类型安全**: 条件函数在编译期检查
- **灵活性**: 可以组合多个条件（`And`, `Or`, `Not`）
- **可测试性**: 条件函数易于单元测试

### 后果

- 用户需要学习条件函数的使用方式
- 条件组合可能增加复杂度

## ADR-009: 事件总线使用字符串类型标识而非反射类型

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 事件路由和订阅

### 决策

事件使用字符串类型标识（`Type() string`）而非反射类型进行路由。

### 理由

- **灵活性**: 字符串类型更灵活，支持自定义事件分类
- **可读性**: 事件类型字符串更易读和调试
- **性能**: 避免运行时的反射类型比较
- **简洁性**: 无需继承基类，任何结构体都可实现事件接口

### 后果

- 用户需要手动实现 `Type()` 方法
- 事件类型字符串需要保持一致性

## ADR-010: 使用优先级枚举而非魔法数字

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 自动配置和执行顺序的优先级定义

### 决策

使用 `OrderPriority` 枚举定义优先级，而非直接使用魔法数字。

### 理由

- **可读性**: `OrderPriorityInfrastructure` 比 `-3000` 更易理解
- **维护性**: 优先级调整只需修改枚举值
- **文档化**: 枚举名称自文档化各层的职责
- **类型安全**: 避免随意使用数字导致的顺序混乱

### 后果

- 新增层级时需要定义新的枚举值
- 用户需要理解各层级的含义

## ADR-011: 早期返回模式而非深层嵌套

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 控制流和错误处理

### 决策

使用早期返回（early return）模式，避免深层嵌套和多余 else 分支。

### 理由

- **可读性**: 扁平的代码结构更易阅读
- **AI 友好**: AI 更容易理解和生成扁平代码
- **减少认知复杂度**: 降低代码的认知负担
- **Go 惯用法**: 符合 Go 的代码风格指南

### 后果

- 函数可能有多个返回点
- 需要确保所有路径都有正确的返回值

## ADR-012: 表驱动测试而非独立测试函数

**日期**: 2024-01-15  
**状态**: 已采纳  
**上下文**: 单元测试编写

### 决策

使用表驱动测试（Table-Driven Tests）覆盖多种场景。

### 理由

- **减少重复**: 多个测试场景共享相同的测试逻辑
- **易于扩展**: 新增测试场景只需添加表项
- **覆盖率**: 更容易覆盖边界条件和错误路径
- **并发支持**: 表驱动测试天然支持 `t.Parallel()`

### 后果

- 测试表可能较长，需要良好的组织
- 复杂场景可能需要额外的辅助函数
